# 🔧 MetaBricks Configuration System

## Overview

MetaBricks now uses a centralized environment-based configuration system that makes it easy to switch between development and production environments. This eliminates the need to manually update URLs, API keys, and other settings across multiple files.

## 🏗️ Architecture

### Configuration Files

- **`config/environments.ts`** - TypeScript configuration for frontend
- **`config/environments.js`** - JavaScript configuration for backend
- **`.env`** - Environment variables (auto-generated by scripts)

### Environment Detection

The system automatically detects the current environment based on:

1. **Environment Variables**: `NODE_ENV` or `METABRICKS_ENV`
2. **Hostname**: `metabricks.xyz` or `metabricks.surge.sh` = production
3. **Heroku**: Presence of `HEROKU_APP_NAME` = production
4. **Default**: Falls back to development

## 🚀 Quick Start

### Development Environment

```bash
# Switch to development
./scripts/switch-env.sh dev

# Start development servers
./scripts/deploy-dev.sh

# Stop development servers
./scripts/stop-dev.sh
```

### Production Environment

```bash
# Switch to production
./scripts/switch-env.sh prod

# Deploy to production
./scripts/deploy-prod.sh
```

## 🔄 Environment Switching

### Automatic Detection

The system automatically detects the environment when the application starts:

```typescript
// Frontend (TypeScript)
import { CURRENT_CONFIG } from '../config/environments';

// Backend (JavaScript)
const { CURRENT_CONFIG } = require('../config/environments');
```

### Manual Override

You can manually override the environment:

```bash
# Set environment variable
export METABRICKS_ENV=production

# Or use the switch script
./scripts/switch-env.sh prod
```

## 🚀 Deployment Scripts

### Development Deployment

```bash
./scripts/deploy-dev.sh
```

**What it does:**
- Sets environment variables
- Starts backend server on port 3001
- Starts frontend server on port 4200
- Opens browser to localhost:4200
- Creates PID files for easy stopping

### Production Deployment

```bash
./scripts/deploy-prod.sh
```

**What it does:**
- Sets environment variables
- Deploys backend to Heroku
- Builds frontend for production
- Deploys frontend to Surge (both domains)
- Opens browser to metabricks.xyz

### Environment Switching

```bash
./scripts/switch-env.sh [dev|prod|status]
```

**Commands:**
- `dev` - Switch to development
- `prod` - Switch to production
- `status` - Show current environment

### Stop Development

```bash
./scripts/stop-dev.sh
```

**What it does:**
- Stops backend server
- Stops frontend server
- Cleans up PID files
- Kills any remaining Node.js processes

## 🔧 Manual Configuration

### Environment Variables

You can override any configuration using environment variables:

```bash
# Backend
export OASIS_API_URL=http://custom-oasis-api.com
export STRIPE_SECRET_KEY=sk_live_your_key_here

# Frontend
export METABRICKS_ENV=production
```

### Local Storage Override

The frontend supports localStorage overrides for testing:

```javascript
// In browser console
localStorage.setItem('metabricks_config', JSON.stringify({
  BACKEND: {
    BASE_URL: 'http://custom-backend.com'
  }
}));
```

## 🐛 Troubleshooting

### Common Issues

1. **Configuration not loading**
   - Check if `config/environments.ts` exists
   - Verify import paths are correct
   - Check browser console for errors

2. **Wrong environment detected**
   - Check `NODE_ENV` or `METABRICKS_ENV` variables
   - Verify hostname detection logic
   - Use `./scripts/switch-env.sh status` to check current environment

3. **Backend not connecting**
   - Verify OASIS API URL is correct
   - Check if backend is running
   - Verify CORS settings

### Debug Commands

```bash
# Check current environment
./scripts/switch-env.sh status

# View backend logs
tail -f logs/backend-dev.log

# View frontend logs
tail -f logs/frontend-dev.log

# Check running processes
ps aux | grep node
```

## 📚 Best Practices

### Development

1. Always use `./scripts/deploy-dev.sh` to start development
2. Use `./scripts/stop-dev.sh` to stop development
3. Check logs if something isn't working
4. Use `./scripts/switch-env.sh status` to verify environment

### Production

1. Test in development first
2. Use `./scripts/deploy-prod.sh` for production deployment
3. Monitor Heroku logs after deployment
4. Verify both domains are working (metabricks.xyz and metabricks.surge.sh)

### Configuration Changes

1. Update `config/environments.ts` and `config/environments.js`
2. Test in development environment
3. Deploy to production
4. Update documentation if needed

## 🔒 Security Notes

- **Never commit** `.env` files to version control
- **Use environment variables** for sensitive data
- **Test keys** are safe for development
- **Live keys** should only be used in production
- **Webhook secrets** should be set via environment variables
